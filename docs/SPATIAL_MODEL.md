# 키워드와 연결되는 학교 공간 개념도

작성·수정: yunze · 2026-10-28

**같은 가상 부지와 카메라에서 서로 다른 세 가지 학교 배치를 비교하는 설명 도구**다. 각 배치는 사람이 직접 작성한 가상 형상이며 실제 학교의 도면·BIM이나 수집 자료에서 자동 생성한 모델이 아니다.

## 2026-10-28 · 키워드별 학교 배치

[Yunze 이슈 #46](https://github.com/yunzecho-eng/school-design-trends/issues/46)에서 기존의 한 학교 형상에 강조 위치만 바꾸던 방식을 확장했다. 키워드를 선택하면 건물의 높이·동 배치·연결 방식이 함께 바뀐다. 같은 부지·시점에서 차이를 비교할 수 있도록 회전·확대·투과 설정은 유지한다.

| 키워드 · 배치 이름 | 가상 학교 배치 | 내부 투과 대상 |
|---|---|---|
| 외부학습공간 · 테라스 중정형 | 2층 후면 교사동과 낮은 양옆 교사동, 중정의 데크·계단형 야외 교실, 녹화 테라스·그늘막 | 오른쪽 작은 실내 학습실의 지정 외피 |
| 지역공유 · 학교·주민시설 분리형 | 높은 후면 교사동과 분리된 전면 도서관·주민 체육관, 공유 광장과 별도 학생 진입로 | 전면 도서관·체육관의 지정 외피 |
| 가변학습공간 · 학습동 군집형 | 네 개의 작은 학습동과 중앙 공용홀, 연결 통로·이동식 구획, 후면 교사동 | 학습동·중앙 공용홀의 지정 외피 |

이는 키워드를 설명하는 설계 대안이며 실제 사업에서 측정한 대표 형태나 성능 순위가 아니다. 현재 필터의 사례는 키워드 근거로만 연결하고 모델의 치수·배치 생성에 사용하지 않는다. 이슈 #46의 테스트·화면 확인 범위는 아래에 기록한다.

## 보는 방법

연도별 분석 또는 사례 상세에서 **키워드를 공간으로 이해하기**를 펼친다. 세 키워드를 누르면 위 표의 학교 배치로 전환한다. 선택한 공간의 위치는 노란 점과 이름표로 표시하며, 텍스트 설명도 해당 배치에 맞춰 바뀐다.

- 회전·확대 슬라이더는 마우스·터치와 키보드 방향키로 조작한다.
- 처음에는 **전체 외관**을 불투명하게 보여 준다. **내부 투과** 슬라이더를 0–100%로 높이면 선택한 배치의 내부 보기 대상으로 지정된 외피만 연속적으로 옅어진다. 주요 교사동과 바닥·내부 공간은 남겨 전체 구성을 읽을 수 있게 한다.
- **전체 외관**은 투과율 0%, 기본 각도·확대율로 돌아간다. **내부 보기**는 현재 시점을 유지하면서 해당 배치의 지정 외피를 숨긴다. **시점 초기화**는 회전과 확대율만 되돌린다.
- 키워드를 바꾸면 학교 형태는 바뀌고 시점·확대율·투과율은 유지한다. 투과 슬라이더는 터치·마우스뿐 아니라 Tab과 방향키로 조작하며 현재 비율을 표시한다.
- 자동 회전은 없다. 그림 대신 공간 설명을 펼쳐 같은 내용을 읽을 수 있다.
- **보고서용 개념도 저장 (SVG)**에는 선택한 배치·현재 시점·키워드뿐 아니라 모델 성격·제작자·형상 출처·이용 조건·자료 범위·근거 출처·가정이 들어간다. SVG의 metadata에도 원래 식별자와 연결 정보를 보존한다.

## 관측과 공간 해석의 경계

`renderSpatialModel(container, {projects, snapshot, onOpenProject, selectedTopic, scopeLabel})`에 부모 화면이 전달한 사업만 근거 사례로 사용한다. `snapshot.projects` 전체에서 다른 연도·지역의 사례를 보충하지 않는다. 연도 화면은 해당 연도의 `project_ids`에 해당하는 전체 사업을, 사례 상세는 해당 사업 하나를 전달한다.

키워드와 같은 `topic_evidence`만 읽고 해당 `source_id`를 출처 목록에 대조한다. 출처가 없으면 연결 미확인, 안전한 원문 URL이 없으면 원문 링크 없음으로 표시한다. 알려진 출처 레코드가 있다는 것과 실제 내용의 검토 완료는 구분한다. 분류·출처의 검토 상태를 그대로 표시한다. 관련 키워드가 없는 조건에는 근거 사례 없음과 개념 설명임을 함께 표시한다.

근거 사례는 앞의 3건을 먼저 표시하고 나머지는 펼침 목록에 둔다. 전체 건수·저장 이미지의 연결 정보에는 모든 해당 사례를 포함하며 펼침 여부로 자료를 제외하지 않는다.

근거는 **사업의 키워드 분류에 대한 근거**이며 가상 모델의 치수·재료·배치에 대한 도면 근거가 아니다. 그림은 집계 건수·분모·사업 내보내기 결과를 바꾸지 않는다. 미래 가정 시나리오나 실제 건물 모델로 표시하지 않으며 학습·에너지·안전 성능을 수치로 추정하지 않는다.

## 구현과 성능

`src/ui/spatial-geometry.js`에 별도 개념 모델 메타데이터와 키워드별 형상 규칙을 둔다. 모델 식별자는 `keyword-campus-concepts-02`이며 저장 SVG에는 키워드별 `layout_id`도 남긴다. 공통 Snapshot에 새 필드를 추가하지 않았다. 단위는 설명용 모델 단위이며 검증된 미터 치수가 아니다. 각 배치의 교사동·창호·중정·데크·공유동·연결 공간·조경을 3차원 꼭짓점으로 만들고 정렬·투영하여 SVG로 그린다. 세 대안은 사람이 작성한 형상 규칙으로 정해지며, API 응답이나 작품집 태그 빈도에 따라 건물 크기·형태를 자동 추론하지 않는다.

패널을 처음 펼칠 때 형상을 만든다. 회전·확대·투과·키워드 입력에만 다시 그린다. 외부 라이브러리·텍스처·모델 다운로드, WebGL, 애니메이션 루프, AI 호출이 없다. 정적 SVG이므로 그래픽 장치 기능에 의존하지 않는다. SVG 파싱 실패에는 텍스트 대안을 남기고 저장 실패는 화면에 알린다. 외부 출처 링크는 HTTP(S)만 허용하고 인증정보가 있는 URL을 거부한다. 화면 문자열은 텍스트 노드, SVG 메타데이터는 XML 이스케이프를 사용한다.

2026-10-19 외관 개선에서 화면 투영과 깊이 정렬의 카메라 축을 직교하도록 맞추고, 지면을 건물보다 먼저 그리도록 분리했다. 기존에는 지면의 평균 깊이로 정렬해 뒤쪽 건물이 지면에 가려질 수 있었다. 보이지 않는 뒷면도 제외한다. 부분 투과는 지정한 외피에만 적용하고, 저장 SVG에도 같은 투과율·시점과 모델 설명을 넣는다. 이미지 전체를 흐리게 만들지 않는다.

모델을 표시하는 화면에서 같은 컨테이너를 재사용하면 로컬 시점과 선택을 유지한다. 반환된 `setTopic(topicId)`로 해당 보고서 키워드와 연결할 수 있다. `destroy()`는 이후 모델 갱신을 중지한다. 컨테이너를 다시 렌더링할 때 이전 인스턴스는 중지된다. 실시간 렌더링 작업이나 GPU 자원이 없어 별도 자원 해제는 필요하지 않다.

## 검증과 남은 범위

2026-10-28 이슈 #46의 전체 테스트는 **273개 통과·실패 0**, 그중 `tests/ui/spatial-model.test.js`의 공간 모델 검사는 **18개 통과**했다. 이전 API 연결의 270개 테스트 기록과 구분한다.

- 형상·SVG 검사: 키워드별 건물 좌표가 실제로 다르고 같은 배치·시점의 반복 생성 결과가 같은지 확인했다. 배치별 기본 불투명 외관, 부분 투과 시 지정 외피만 변경, 지면과 건물의 순서, 카메라 축, 근거 필터·출처·메타데이터·문자열 삽입 방지 검사를 유지했다.
- 확대·회전 경계: 확대 130%에서 지붕이 잘리던 문제를 공통 카메라 축척 조정으로 수정했다. 회귀 검사에서 세 배치의 모든 건물 꼭짓점과 이름표가 검사한 회전각별 SVG 영역 안에 들어오는지 확인했다.
- 그림 비교: 세 배치의 SVG를 직접 렌더링해 건물 높이·배치와 외관이 서로 다르게 보이는지 확인했다.
- DOM 이벤트 모의 실행: 비공개 임시 검증 환경에서 실제 `renderSpatialModel`의 세 키워드 버튼을 눌러 형상 메타데이터·설명·근거가 바뀌고 회전 76°·확대 110%·투과 50%가 유지되는지 확인했다. 저장 SVG의 현재 키워드·자료 범위, 근거 없는 자료로 다시 그린 뒤의 시점 보존·빈 근거 표시, 이전 인스턴스가 현재 화면을 갱신하지 않는 것도 확인했다. 이 검사는 별도 DOM 시뮬레이션이며 실제 브라우저 수동 조작을 대신하지 않는다. 제품 의존성은 추가하지 않았다.
- 로컬 브라우저: 2025년 연도별 패널을 열어 외부학습 배치 표시, 해당 연도 사업 55건과 연결 근거 45건을 확인했다. 이후 브라우저 연결 오류로 수동 키워드 전환·모바일 조작·전체 저장 흐름은 이번 실행에서 확인하지 못했다. 조절값 유지와 SVG 출력은 코드 검토·자동 검사·DOM 이벤트 모의 실행 근거이며 수동 UI 검증 완료로 표시하지 않는다.
- 비밀값 검사: 추적 파일과 Git 제외 대상이 아닌 파일 121개를 설정된 인증키 4개의 값과 대조해 노출 0건을 확인했다.

실제 배포 커밋과 공개 화면 확인 결과는 이슈 #46의 관련 PR 댓글에 별도로 기록한다.

공간 모델에 수집 자료를 이용한 형상 자동 생성, AI 추가 학습, 사진 기반 복원, 치수 도면·IFC 변환을 연결한 것은 아니다. 더 사실적인 실제 학교 모델에는 사용권을 확인한 도면/IFC와 검증된 치수, 출처별 가정 기록이 필요하다. 모델·코드에 공개 라이선스를 새로 부여하지 않았으며 외부 재사용 조건은 팀의 라이선스 결정 뒤 정리한다.
